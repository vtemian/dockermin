# Architecture Reference

## Overview

**Dockermin** is a GRPO (Group Relative Policy Optimization) project that fine-tunes a Qwen 2.5 Coder 7B LoRA adapter to minimize Dockerfiles. Unlike text-similarity reward signals, dockermin trains against *real* `docker buildx` builds and `docker run` tests: every rollout's reward comes from actually building the model's rewritten Dockerfile, running the test command inside the resulting image, and measuring the image-size reduction relative to the baseline. The reward is a pure function (parse/build/test gates -> dense size-reduction signal -> shape bonuses) so it is testable offline and identical between the prime-rl training loop and the offline eval harness. Training data is scraped from public sources, validated through the same build+test gates, augmented with deliberately-bloated synthetic variants generated by Claude, and pushed to the Hugging Face Hub.

## Tech Stack

| Layer | Technology |
|-------|------------|
| RL training | prime-rl (GRPO), verifiers `SingleTurnEnv` + `Rubric` |
| Base model | Qwen/Qwen2.5-Coder-7B-Instruct + PEFT LoRA |
| Inference | vLLM (pod / eval), HF transformers + peft (CLI) |
| Build/test sandbox | `docker buildx build` (subprocess), docker SDK (size inspect + `docker run`) |
| Dataset sources | docker-library/official-images, docker/awesome-compose, GitHub code search (via `gh` CLI) |
| Synthetic variants / agent baseline | `claude -p` (Claude Code headless, Sonnet 4.6) |
| Eval baselines | OpenAI SDK (GPT-4o), Anthropic SDK (Sonnet), hadolint, SlimToolkit |
| Data store | JSONL on disk -> Hugging Face Hub (`vtemian/dockermin-v0`) |
| Lang / gates | Python 3.11, ruff + mypy-strict, pytest |

## Data Flows

### 1. Dataset build (scrape -> annotate -> variants -> HF)

```
1. scrape.py fetches candidates from three sources (run_scrape.py orchestrates):
   - fetch_official_images(limit)
       _gh_api("repos/docker-library/official-images/contents/library")
       -> per name: _candidate_from_manifest_entry -> _manifest_dockerfile_url
          (_parse_official_manifest -> _manifest_raw_url) -> _fetch_dockerfile
       -> Candidate(source="official-images:<name>", ecosystem=_infer_ecosystem(name))
   - fetch_awesome_compose(limit)
       _gh_api("repos/docker/awesome-compose/contents") -> _compose_candidates_for_entry
       -> _walk_awesome_compose_dir (recurses subdirs) -> _candidate_from_compose_file
   - fetch_github_search(limit)
       _collect_search_items(query_variants) -> _search_code_query -> _search_code_page
       -> _candidate_from_code_hit (dedup by sha256 via _is_new_content,
          ecosystem via _ecosystem_from_dockerfile)
   run_scrape.py writes Candidates as data/raw/candidates.jsonl.

2. run_annotate.py bulk-annotates each candidate through annotate.py gates:
   For each candidate Dockerfile:
     infer_test_cmd(df_text) -> (test_cmd, expected_substring)  # skip if (None, None)
     annotate_one(df, test_cmd, expected_substring):
        parse_gate(df)                         # dockerfile.parse_string + MIN_COMMANDS check
        -> build_gate(df) -> _run_buildx       # `docker buildx build --load` subprocess
                                               #   wall-clock timeout actually kills the build;
                                               #   cache-from/cache-to amortize across rollouts
           -> _docker_client().images.get(tag).attrs["Size"]   # size inspect
        -> run_test_gate(tag, cmd, expected)   # docker run, match exit 0 + expected substring
                                               #   refuses empty expected_substring (anti-hack)
     Passing triples written per-run, then atomically merged into curated/triples.jsonl
     (dedup on candidate id). --lockfile guards concurrent runs (ops.acquire_lock).

3. synthetic_variants.py augments the curated set with bloated variants:
   For each base triple (read_jsonl):
     generate_variant(...) -> `claude -p ... --output-format json` (Sonnet 4.6 headless,
        no API key needed) -> extract_dockerfile(meta["result"])
     annotate_one(variant, base test_cmd, expected)   # variant MUST still build + pass
     append_jsonl(out, rec)  with is_synthetic_variant=True, base_id link
   Append-mode + dedup on startup (existing ids) makes repeated/respawned runs resume,
   not truncate. --lockfile for exclusive run.

4. push_to_hf.py uploads the curated triples.jsonl as the HF dataset
   vtemian/dockermin-v0.
```

### 2. Reward + eval (prime-rl reward; offline baseline leaderboard)

```
TRAINING REWARD (prime-rl GRPO):
1. prime-rl loads the verifiers env via configs/dockermin_*.toml ([[env]] id="dockermin-env").
   verifiers resolves "dockermin-env" -> module "dockermin_env" and calls
   dockermin_env.load_environment():
     load_dataset("vtemian/dockermin-v0") -> map each row to {prompt, info, answer}
        prompt = [SYSTEM_PROMPT, USER_TEMPLATE.format(dockerfile/test_cmd/expected)]
        info   = {baseline_size, test_cmd, expected_substring}
     -> vf.SingleTurnEnv(dataset, rubric=vf.Rubric(funcs=[dockermin_reward], weights=[1.0]))

2. Per rollout, the model emits a completion; verifiers calls
   dockermin_reward(completion, info):
     _completion_text(completion)          # str or list[message] -> flat text
     -> extract_dockerfile(text)           # first fenced ```dockerfile block
     -> parse_gate(new_df)                 # fail -> compute_score(parse_ok=False, ...)
     -> build_gate(new_df)                 # fail -> compute_score(build_ok=False, ...)
     -> run_test_gate(tag, info["test_cmd"], info["expected_substring"])
     -> compute_score(parse_ok, build_ok, test_ok, command_count,
                      baseline_size, new_size, dockerfile_text):
          gate ladder: first failing gate fixes the score (PARSE/TOO_FEW/BUILD/TEST)
          dense: reduction = (baseline_size - new_size)/baseline_size, clamped [0,1]
          shape: _shape_bonus (distroless/alpine/multi-stage/cache-hygiene)
                 + _shape_penalty (:latest, unpinned bare FROM, empty `FROM scratch`)
          return min(1.0, 0.5 + 0.5*dense + shape)

OFFLINE EVAL (run_eval.py -> leaderboard.py):
3. run_eval.py iterates triples x baselines via baselines.run_one(name, triple):
     registry baselines: qwen_zs, gpt4o, sonnet_zs, hadolint, slim, manual, dockermin
       (agent_loop self-registers via agent_loop.register_baseline)
     Each baseline produces a rewritten Dockerfile then calls _entry -> _verify ->
       annotate.annotate_one (same build+test gates as training) -> EvalEntry
       {baseline, triple_id, new_size_bytes, test_passes, elapsed_s, error}
     A safety-net `except Exception` (BLE001, documented) ensures one bad Dockerfile
     never crashes the eval loop. EvalEntry rows written as JSONL.

4. leaderboard.py aggregates the EvalEntry JSONL into a markdown table:
   per baseline -> test-pass rate, mean size reduction conditional on pass.
```

## Key Decisions

| Decision | Why |
|----------|-----|
| **prime-rl over raw verifiers** for the training loop | prime-rl provides the GRPO trainer + vLLM inference + LoRA hotswap (filesystem broadcast) wiring; verifiers alone is just the Environment/Rubric abstraction. LoRA hotswap lets inference swap adapters without full reload. |
| **`docker buildx build` subprocess over docker SDK `images.build()`** | The SDK `timeout` is an HTTP idle timeout only — a stuck `RUN` keeps streaming logs and never trips it, holding a worker thread forever. The subprocess `timeout` kills the build on the wall clock. Bonus: `--cache-from`/`--cache-to` (BuildKit) actually work, so apt/pip/npm caches amortize across rollouts. |
| **`claude -p` (Claude Code headless) over the Anthropic SDK** for synthetic variants + agent-loop baseline | Claude Code handles auth via its own keychain/login, so no `ANTHROPIC_API_KEY` needs to live in the environment. Cost: the default system prompt + tool defs trigger ~25k cache_creation tokens per session (`--bare` would strip this but needs the API key), so we pay the cache cost. |
| **env_id `"dockermin-env"` -> module `dockermin_env`** | verifiers resolves an `env_id` to a Python module via `package_module_name(env_id)` (`-` -> `_`). The `verifiers.environments` entry point in pyproject is decorative/unused at runtime; what matters is the importable module name matching the resolved id. |
| **Append-mode + startup dedup for synthetic variants** | The Claude-driven generation run is long and prone to chaotic respawns. Appending each validated variant and deduping on existing ids at startup makes repeated/interrupted invocations resume and accumulate progress instead of truncating prior work; `--lockfile` (flock) prevents concurrent writers. |
| **Reward is a pure `compute_score` function** | Same scoring path runs in the prime-rl training reward and the offline eval harness, and it is unit-testable without docker. Gates (parse/build/test) are isolated so failures short-circuit deterministically. |
| **Reject empty `expected_substring` at the gate (defense in depth)** | `"" in anything == True`, so an empty expected substring would make every test trivially pass — a reward-hacking surface. `run_test_gate` refuses it; `infer_test_cmd` drops ecosystems (e.g. Go) where it can't supply a meaningful expectation. |
| **`scripts/` are CLI glue, not library** | The pod ops scripts get per-file lint ignores (T20/S603/S607/ANN/complexity); shared logic that deserved testing (jsonl + lockfile) was extracted into `src/dockermin/ops.py`. |
